Make articlegen get open-access full text from the `papers` CLI (the paperfetch project, a separate private repo installed as the `papers` console script) instead of only Europe PMC via PMCID, so non-biomedical and arXiv papers stop being abstract-only (closes #150 and #151 without writing our own PDF parser).
1. New `articlegen/paperfetch.py`: `fetch_via_papers(doi: str, timeout: float = 120) -> str`. Runs `papers get <doi>` with `subprocess.run` (argv list, no shell, `capture_output`, `text=True`, timeout), env inherited plus `PAPERS_MAILTO` defaulting to `OPENALEX_MAILTO`/`UNPAYWALL_EMAIL` if unset. Parse the single JSON object on stdout; on `status == "ok"` read the file at `read` (UTF-8, errors ignored) and return its text; any other status, non-zero exit without JSON, timeout, JSON error, or missing file → return `""`. `available() -> bool` caches `shutil.which("papers") is not None` for the process; env `ARTICLEGEN_PAPERS_CMD` overrides the executable path (split with `shlex`, so `python -m papers` works). Never raise into the pipeline; log one line via the passed `log` callable on the first unavailability per process (`papers CLI not installed; full text limited to Europe PMC`).
2. `articlegen/sources.py` `fetch_full_text(paper, use_cache=True, log=lambda msg: None)`: if `paperfetch.available()` and `paper.doi` → try `fetch_via_papers(paper.doi)` first, keyed in `_fulltext_cache` by DOI; non-empty result wins. Otherwise (no DOI, `papers` missing, or it returned `""`) → the existing Europe PMC PMCID path unchanged. Do not change `resolve_pmcid`, `_parse_fulltext_xml`, `full_text_excerpts`, `full_text_order`, ranking, or the writer/verify excerpt contract.
3. `articlegen/pipeline.py` full-text loop: when `paperfetch.available()`, a paper with a DOI is fetchable even without `pmcid`/`is_open_access` — call `fetch_full_text` for it (still counts against `MAX_FULLTEXT_REQUESTS`; still only direct/related, same `full_text_order`). Keep `resolve_pmcid` as the fallback for DOI-less-PMCID papers only when `papers` is unavailable. The tallies/log lines (`no_open_access`, `fetch_failed`, `stopped because`) keep their meaning; add the count fetched via `papers` to the "full text retrieved" line, e.g. `(3 via papers, 1 via Europe PMC)`.
Where: new articlegen/paperfetch.py, articlegen/sources.py, articlegen/pipeline.py, tests/test_offline.py, README.md (one short section: install paperfetch, `PAPERS_MAILTO`, hosted deploy does not have it yet), CLAUDE.md if it lists modules
Done means: offline tests (mock `subprocess.run` and `shutil.which`, no network) cover: `ok` JSON → text returned and cached by DOI; `queued_ckn`/`no_doi`/exit 1/timeout/bad JSON/missing file → `""` and Europe PMC path still runs; `papers` not on PATH → behaviour identical to today (existing tests unchanged); `ARTICLEGEN_PAPERS_CMD="python -m papers"` splits correctly; pipeline loop fetches a DOI-only, no-PMCID paper when `papers` is available and skips it when not; `python tests/test_offline.py && python tests/test_journal_conformance.py` both pass.
Out of scope: importing the `papers` package, vendoring paperfetch, any PDF parsing in articlegen, touching the CKN queue, Dockerfile/render.yaml changes (paperfetch is private and not pip-installable from Render yet), changing excerpt sizes or ranking, new dependencies.
